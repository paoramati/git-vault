invariants:
  - After lock, git push to any remote fails, including a remote added after locking
  - After lock, fetch still works with the original URLs
  - unlock restores exactly the push configuration that existed before lock
  - lock and unlock are idempotent
  - An existing user pre-push hook is never lost
edge_cases:
  - Repo with no remotes
  - Remote with an explicit pushurl already set
  - Several remotes
  - Existing pre-push hook (must be preserved and restored on unlock)
  - Running inside a worktree
  - Running outside a git repo (clear error, exit 1)
acceptance_criteria:
  - git vault lock and git vault unlock implemented as cmd_lock and cmd_unlock
  - Original push config is stored under a vault.* git config section so unlock can restore it
  - tests/lock.bats covers every invariant and edge case listed

## Rule
Two independent layers: push URLs replaced with an invalid value, and a pre-push hook that refuses. Either alone must stop a push.
