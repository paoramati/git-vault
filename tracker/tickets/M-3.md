title: Prune old backups safely
type: mechanic
status: ready
priority: 1
parent: E-1
depends_on: [M-2]
labels: [agent-ok, risk:high]
invariants:
  - Only files matching this repo's bundle and patch naming pattern are ever deleted
  - The newest N bundles are kept (default 14, --keep N)
  - The newest bundle that passes verify is never deleted, even if it is outside the newest N
  - Prune never runs if the backup that just ran failed
edge_cases:
  - Other repos' bundles in the same folder (untouched)
  - Unrelated files in the folder (untouched)
  - Fewer than N bundles (nothing deleted)
  - The newest bundles are corrupt (an older valid one survives)
  - A file is locked during delete (retried, then skipped with a warning, never a failure of the backup)
acceptance_criteria:
  - Pruning runs at the end of git vault backup; --keep N sets the count
  - tests/prune.bats covers every invariant and edge case listed
